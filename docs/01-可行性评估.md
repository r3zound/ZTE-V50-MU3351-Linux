# mu300-linux 移植到 ZTE V50 的可行性评估

> 评估日期：2026-10-09
> 目标仓库：https://github.com/dikeckaan/mu300-linux （最新 release **v2026.10.11**）
> 目标设备：本机 ZTE V50（`192.168.0.1:5555`，固件 `V50_V1.0.0B15`）
> 所有数据均从设备实测取得，非推测。

---

## 结论

**可行性极高。V50 与 mu300-linux 支持的 ZTE F50 是同一块板 `ums9620_2h10_feimao`，不是"类似机型"，而是同一硬件平台。**

唯一的实际卡点是安装器的机型识别字符串匹配不到 V50，需要回答一次确认（回答 `yes` 即可），
或给 `install.sh` 打一个 1 行的补丁。

## 唯一的卡点：机型识别

`install.sh:115-124` 用字符串匹配判断机型：

```sh
model="$(su_do 'getprop ro.product.model') / $(su_do 'getprop ro.product.device')"
# V50 实际得到:  "V50 / MU3351"

case "$model" in
    *U30Air*|*U30_Air*|*"U30 Air"*) DEVICE=u30air ;;
    *MU300*|*F50*|*mu300*) DEVICE=f50 ;;
    *) ask go "This does not look like a ZTE F50/MU300 or U30 Air. Continue anyway? (yes/no)" no
       [ "$go" = yes ] || exit 1
       DEVICE=f50 ;;
esac
```

`"V50 / MU3351"` 不含 `MU300`（是 MU3351）、不含 `F50`，因此落入 `*)` 分支。

**处理方式二选一：**

1. **零改动**：提示时输入 `yes`。随后 `DEVICE=f50`，走 F50 全部流程 —— 这正是我们要的，
   因为 V50 就是这块板。
2. **打补丁**（推荐，可复现）：把 `install.sh:121` 改为

   ```sh
   *MU300*|*F50*|*mu300*|*V50*|*MU3351*) DEVICE=f50 ;;
   ```

   Magisk 路线同理，在 `/data/adb/mu300-install.conf` 里写
   `MU300_DEVICE=f50`（该 key 已支持，仅 `/data/adb` 下生效）。

## 预期可获得的能力

来自 v2026.10.11 release，全部为实测已支持项：

- Ubuntu 24.04 / 26.04 LTS、OpenWrt 25.12（含 `openwrt-luci` 控制面板）
- 三套内核：vendor 5.4 / mainline 6.18 LTS / mainline 7.2，均带 `/dev/kvm`
- 5G 移动数据共享给 WiFi 与 USB 客户端；SMS、USSD
- WiFi 热点（5 GHz / 2.4 GHz）+ WiFi 客户端模式（WPA2 / WPA2-3 混合；**纯 WPA3 不支持**，该驱动无 SAE）
- USB 网络（`192.168.77.1`）+ USB 串口控制台 + SSH
- 蓝牙、Mali GPU（OpenCL 3.0，无显示输出）
- `mu300-toolkit` 菜单式管理、`mu300-next-boot` 一键回 Android、失败 5 次自动回滚 Android
- VPN extra（Xray / sing-box）、VLESS、kill switch、Tailscale 走隧道

### 已知限制（V50 同样适用）

- **无显示输出**（USB-C 的 PD 芯片不应答，HDMI 不通）—— 无头机器，走 SSH / 网页
- **无声音**（无喇叭无麦克风）
- 无 SD 卡槽 → 只能装内部 eMMC 的 32.39 GiB 空闲区（完全够用，不影响）
- V50 是 CPE 无电池 → 对应 F50 配置（`DEVICE=f50`），**不要**选 u30air
- V50 的 LED 与 F50 不同（V50 是 `sc27xx:blue/green/red` + `aw_led`，
  F50 是 network blue/white/red + WiFi）。装好后 `mu300-led test` 可能对不上，
  属外观问题，不影响网络与数据功能，可后续单独修 LED fragment

## 风险评估

| 风险 | 等级 | 说明 |
|---|---|---|
| 变砖 | **低** | Android 分区不写；只写 `boot_b`（当前 Android 在 `_a`）和 `misc` 32 字节；失败 5 次自动回 Android；`uninstall.sh` 可完全还原 |
| 需要 SPD/BROM 救砖 | 极低 | 仅在写错分区/断电等极端情况 |
| Modem 挂 | 低 | modem 校准/IMEI 在 `prodnv`、`calinv` 等分区，安装器不碰；**装前务必跑 `tools/backup-device.sh`** |
| 6.18 偶发启动挂死 | 中 | 约 1/20 概率，会自动回 Android，`su -c mu300-linux` 可再进。**首次建议用 5.4**（测试最久） |

## USB 网络模式（RNDIS）的正确做法

> 补充于 2026-10-10。**此节更正一个错误结论**：早期本文档曾写「RNDIS 实测无效，USB 仍为 NCM」，
> 那是**错的**。RNDIS 在本设备上完全可用，我当时用错了方法。

### 我错在哪

我改的是**内核命令行**：给 `boot/build-boot-image.py` 加了一个 `MU300_USBNET` 环境变量，
让它在 boot 镜像头偏移 44 处追加 ` MU300_USBNET=rndis`。这条路走不通，而且有害：

1. **无效**：`boot/init:273` 把 `MU300_USBNET` 当**环境变量**读（`${MU300_USBNET:-ncm ecm}`），
   不是从 `/proc/cmdline` 解析。设备上该变量为空 → 永远走默认 `ncm ecm`。
   （实测：`dmesg` 里 `stage=usb-net-function ncm`，USB 枚举为 CDC NCM。）
2. **有害**：它把 boot 镜像头偏移 44 的 11 字节从 `loglevel=5\0` 改成了 `loglevel=5 MU...`，
   而 Android 侧的 `switch.sh` 正是靠这 11 字节识别 Linux 镜像 →
   **设备从此再也切不进 Linux**，报错还指向「这是旧版 Android 镜像」。

### 正确的机制（上游设计 D12）

面板页 `http://192.168.77.1/cgi-bin/luci/admin/modem/device` 的「USB 网络模式」一节，
调的是一次 ubus 调用：

```
mu300dash usb_set { kind:"net", value:"rndis", scope:"permanent", auto:"1" }
```

（前端声明见 `/www/luci-static/resources/mu300/common.js:30`，
调用点见 `/www/luci-static/resources/view/mu300/device.js:126`。`value` 取 `ncm` / `ecm` / `rndis`。）

它做的是：把选择写进**所选系统的** `etc/mu300/usb-net`（本机内容为 `rndis\n`，权限 0600）。
然后每次开机，`boot/init` 在 `pick_root` 之后读这个文件（`boot/init:515`）：

```sh
usb_net_policy() {                       # boot/init:515
    [ -z "${MU300_USBNET:-}" ] || return 0        # 命令行变量优先权最高（本设备从未设置，故为空）
    case $(cat "$1/etc/mu300/usb-net" 2>/dev/null) in
        ncm)   echo 'ncm ecm' ;;
        ecm)   echo 'ecm ncm' ;;
        rndis) echo 'rndis ncm ecm' ;;   # ← 该内核做不出 RNDIS 时依次退回
    esac
}
```

若与当前已绑定的功能不同，就 `teardown_usb_gadget` + `setup_usb_gadget` **重绑一次**，
并把实际生效的功能写进 `/run/mu300/usb-net-applied`（K8 的一次性凭据）。

### 本机实测证据

| 证据 | 值 |
|---|---|
| `/etc/mu300/usb-net` | `rndis\n`（`od -c` 确认，mtime 与操作时刻一致） |
| `/run/mu300/usb-net-applied` | `rndis` |
| gadget functions | `acm.GS0`、`rndis.rn0` |
| gadget config c.1 | `f1`、`f2` |
| `/proc/cmdline` | 只有 `NET=rndis`（Unisoc 自己的参数，`boot/init` 不读），**没有** `MU300_USBNET` |
| `mu300dash usb_get` | `{"net_mode":"rndis","net_scope":"permanent","net_auto":1,"net_available":1}` |
| PC 侧 | 出现「Remote NDIS based Internet Sharing Device」，拿到 LAN 地址 `192.168.77.247` |

### 两点注意

- **`scope`**：`permanent` = 永久写进 `etc/mu300/usb-net`；另有一次性语义（只影响下一次启动）。
  `auto=1` 才是「下次重启生效」；`auto=0` 是「只存不用」。
  UI 上的确认文案就是这么写的，`device.js:122` 原文：
  *"The network mode applies on the next reboot"* / *"Save the selection only"*。
- **会被整机安装覆盖**：`update` 模式的 `android-install.sh` 是 `rm -rf` 后 `cp -a` 整体覆盖
  `etc/mu300/`，所以面板设的值会被下一次整机安装清掉，装完要重设一次。**这不是 bug，是安装语义。**

### 不点网页的等效做法

```sh
# 设备侧（OpenWrt 里）
ubus call mu300dash usb_set '{"kind":"net","value":"rndis","scope":"permanent","auto":"1"}'
ubus call mu300dash usb_get          # 复核：net_mode 应为 rndis
```

```powershell
# 从 PC 用本仓库封装（已实测，返回 {"ok":1}）
.\tools\mu300-api.ps1 -Call 'mu300dash usb_set' -Params '@params.json'
#   params.json: {"kind":"net","value":"rndis","scope":"permanent","auto":"1"}
```

**RNDIS 与 WiFi 会互相干扰**：两条链路在同一子网会让设备产生两条重复的
`192.168.77.0/24` 路由，回包走 USB，于是 WiFi 客户端连 ping 都不通。
根因与修法见 `docs\04-WiFi与DHCP根因分析.md`（`10-mu300-usb` 清理顺序缺陷）。
**日常建议只留 WiFi**：要 USB 就把 WiFi 断开，或把 `usb-net` 设回 `ncm`。

## 建议执行路径

> **完整的、可被别人复刻的逐步操作，见 `docs\05-一键复刻指南.md`**（含备份 → 17 步补丁 → 安装 →
> 装机后设置 → 验收清单）。下面只是骨架。

```sh
# 0. 备份（必做，含 IMEI，丢了自己都修不回来）
.\tools\backup-v50-partitions.ps1

# 1. 只读检查，不写任何东西
.\install.ps1 -Check

# 2. 打补丁（17 步，幂等；机型识别只是第 1 步）
.\tools\apply-v50-patches.ps1

# 3. 安装，首选 OpenWrt，内核选 5.4
.\install.ps1 -Lang zh -NoSelfUpdate -Answers <file>

# 4. 装机后设置（决定能不能拿到 IP，别跳过）
#    见《一键复刻指南》第 4 节：lan 防火墙区含 br-lan、mu300-hw 无 BOM、USB 网络模式

# 5. 进 Linux
ssh root@192.168.77.1

# 6. 想回 Android
sudo mu300-next-boot android && sudo reboot
```

## 复核命令

本次评估用到的实测命令，可自行复现：

```powershell
$adb="$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$adb connect 192.168.0.1:5555
$adb shell "getprop ro.hardware"          # ums9620_2h10_feimao
$adb shell "su -c id"                     # uid=0 (Magisk)
$adb shell "uname -a"                     # 5.4.254-android12
$adb shell "dmesg | grep -i sprd-wlan"    # sc2355
```
