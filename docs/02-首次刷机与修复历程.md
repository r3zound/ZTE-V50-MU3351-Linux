**我一开始把 `192.168.77.11` 当成设备 DHCP 分配的地址，判错了。**

那是**你手动设置的静态 IP**。所以实际情况是 **DHCP 确实没有工作**。

修正后的症状描述：

> 无线热点能广播、能关联，但**既不发 IP（DHCP 不工作），也不开 SSH/LuCI**。

这个修正很重要——它说明问题不只是「SSH 慢」，
而是 OpenWrt 的网络服务链（dnsmasq + dropbear + uhttpd）整体缺失。

## 四、你提的两个问题

### 问题一：能不能默认改成 RNDIS？—— 能，已实现并验证

**为什么必须改**：这台 PC 是 Windows 10 IoT 企业版 LTSC 21H2，它的 `usbncm.inf` 虽然匹配设备的
兼容 ID（`USB\Class_02&SubClass_0d&Prot_00`），但**缺少 catalog 签名文件 `UsbNcmFn.cat`**，
全盘和 WinSxS 都搜不到，`pnputil` 直接拒绝（"第三方 INF 不包含数字签名信息"）。

而 **RNDIS 完全不需要装驱动** —— `rndis.sys` 是 Windows 内置的。

**实现**：`boot/build-boot-image.py` 现在支持用环境变量把 `MU300_USBNET=rndis` 写进内核命令行。

```powershell
$env:MU300_USBNET = 'rndis'
```

**已验证**（构建两次镜像后直接读 boot header 第 44 字节）：

```
默认  : loglevel=5
rndis : loglevel=5 MU300_USBNET=rndis
```

init 里的 RNDIS 分支是现成的（`boot/init` 的 `setup_usb_gadget` + MS OS descriptors），
Windows 会通过 OS descriptor 自动绑定 `rndis.sys`。

### 问题二：无线 DHCP —— 确实没有分配地址（我一开始判错了）

见第一节。真实情况是 DHCP 没工作，热点能连但服务链整体缺失。

这一点直接影响回退 —— 见第六节。

第 3 项思路：**让启动路径上任一步卡住都不再拖死整机**，这样即使有环节有问题，SSH 也能起来，我们就能进去看日志。

第 4 项思路：**让「坏启动」不再被标记成好启动**，从而保留回退 Android 的能力。

## 六、如何回到 Android（重点：一个上游缺陷）

### 为什么断电重启不管用

**根因：OpenWrt 每次开机都会把两道回退计数清零。**

设备其实有**两道**独立的回退计数：

| 计数 | 位置 | 维护者 |
|---|---|---|
| LK 的 `tries_remaining` | `misc` 偏移 2048 的 `BCAB` 块 | 引导器每次启动减 1，减到 1 就回 Android |
| initramfs 的 `boot-tries` | Linux 分区 `.mu300/boot-tries` 文件 | initramfs 每次启动加 1，超过 5 就回 Android |

而 `openwrt/overlay/etc/init.d/mu300-post`（START=99）里有这段：

```sh
procd_open_instance bootok
procd_set_param command /bin/sh -c "sleep 30; exec /opt/mu300/bin/mu300-next-boot --rearm"
procd_close_instance
```

`mu300-next-boot --rearm` 会**同时**做两件事（源码第 69-72、106 行）：

1. 把 LK 的 tries 重写成 `N+1 = 6`
2. **清空 initramfs 的 `boot-tries` 为 0**

而且它**是无条件的** —— 不检查 SSH/USB 是否真的可用。
Ubuntu 版的 `mu300-boot-ok` 会真检查「USB 网络和 SSH 起来了没有」，**OpenWrt 版缺这个检查**。

**结论**：只要 OpenWrt 每次都能跑到 S99，每次开机两道计数都被清零 →
**无论断电多少次，设备都永远回不到 Android**。这正好解释了你遇到的现象。

> 补充证据：安装时写入的 `misc` 初始值解码后是 `tries=2`。
> 按常理最多 2 次启动就该回 Android。你的设备却每次都能回到 Linux ——
> **这反证了 rearm 确实在运行**。

### 恢复方法（按成功率排序）

#### 方法一：提前断电（推荐，零工具）

关键：**在 OpenWrt 跑到 S99 之前把电断掉**，让 rearm 来不及执行，计数得以累积。

时间线（估算）：

```
t=0        上电
t≈1-2s     LK 减 tries，启动 slot b
t≈3-8s     内核启动
t≈8-15s    initramfs 挂载根文件系统、计数、switch_root
t≈15-30s   OpenWrt procd 开始跑 rc.d
t≈30-60s   跑到 S99（mu300-post），派生出 bootok 实例
t≈60-90s   ★ rearm 执行 → 两道计数全部清零 ★
```

**所以要在 t≈10~20 秒时断电** —— LK 已经减过数，又远早于 rearm。

操作步骤：

1. 记下时间，**拔掉 USB 供电**（V50 靠 USB 供电，拔线即断电）
2. 等 5 秒
3. 插上，**默数到 8~10 秒**，立刻拔掉
4. 重复第 2-3 步，**共 6~8 次**
5. 最后一次**插上后不要再拔**，让它正常启动，等约 2 分钟

> 多拔几次无害（计数减到 1 后 LK 会直接进 Android，之后怎么拔都进 Android）。
> **关键是每次都要早拔** —— 只要有一次让 OpenWrt 跑完 rearm，前面的努力就归零。

#### 方法二：USB 串口控制台（如果能通，最省事）

Linux 起来后 USB 会枚举出 `USB 串行设备 (COM12)`，那是 ttyGS0 上的控制台
（OpenWrt 的 inittab 里有 `ttyGS0::askfirst:/usr/libexec/login.sh`）。

如果能拿到 shell，一条命令立刻解决：

```sh
mu300-next-boot android
reboot
```

用 PuTTY 连 COM12，**115200 8N1，无流控**。

> 注意：首次安装那次启动时 inittab 里还没有这一行（由 uci-defaults 首次运行时追加），
> 所以第一次可能进不去；第二次之后的启动才有。

#### 方法三：BROM 模式恢复 `misc`（保底，一定能成）

你手上有全套工具：

- `V50\一键刷分区、备份还原工具\`
- `V50\短接触点.png`（进 BROM 的短接点）
- 本次备份 `V50\backup\2026-10-09-pre-install\misc.img`（刷机**之前**的原厂状态）

把 `misc.img` 刷回去，设备就恢复成「Android 为默认启动」。
这是最后手段 —— 需要短接触点进 BROM，但**理论上一定能恢复**，
因为 `misc` 分区完好无损，且我们有完整备份。

### 怎么确认已经回到 Android

**不要看 WiFi** —— Linux 和 Android 的热点同名（`<你的热点名>`），看 WiFi 判断不了。

看 USB 和 adb：

| 状态 | Linux | Android |
|---|---|---|
| USB 设备 | `USB Composite Device` + `COM12` + `CDC NCM` | 变成 ZTE 的 Android 设备，上面这些消失 |
| `adb` | 不响应 | `adb connect 192.168.0.1:5555` → `device` |

用监控脚本自动盯：

```powershell
& "D:\OneDrive\User\Network\CPE\V50\tools\wait-for-android.ps1"
```

它每 5 秒检查一次 USB 形态和 adb，一旦 Android 回来就打印 build 号和 slot，并提示下一步。

## 八、这次刷机的经验教训

1. **机型补丁必须改三处**：`install.ps1` 有三处独立正则（`:219` / `:372` / `:416`），
   不共用 `install.sh` 的逻辑。只改 sh 会导致 `-Check` 照样弹确认框。

2. **别在 CDC NCM 驱动上浪费时间**：Windows 10 IoT LTSC 的 `usbncm.inf` 缺 catalog，
   装不上；自签名要 WDK。**直接用 RNDIS**，零驱动依赖。

3. **OpenWrt 版的 re-arm 是无条件的**（上游缺陷）：它让坏启动被标记为好启动，
   并且清空两道回退计数，导致设备**再也回不到 Android**。已由补丁 4 修掉。

4. **判断设备状态不要靠 WiFi**：Linux 和 Android 的热点同名，必须看 USB 形态或 adb。

5. **Windows 上编辑含中文的文件要指定 UTF-8**：
   PowerShell 5.1 的 `Get-Content`/`Set-Content` 默认 ANSI，往返一次就把 UTF-8 中文写成乱码。
   用文件编辑工具，或显式 `[IO.File]::ReadAllText($f, [Text.Encoding]::UTF8)`。
